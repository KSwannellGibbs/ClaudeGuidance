Getting more out of every Claude message

No coding background needed. Small changes to how you converse with Claude can meaningfully cut token use, without changing what you get done.

We're on a Team plan and starting to hit usage limits

This guide covers Chat specifically. See Getting More Out of Every Cowork & Code Session for the other half of the picture.

1

What burns tokens fastest

Six things that quietly drive up usage in Chat

1

Long, sprawling conversations

Every message and reply stays in context, so the longer a chat runs, the more each new response costs.

2

Big file uploads

Large documents and data files eat context fast, especially if you re-upload the same file in every new chat.

3

Web search, Research & connectors left on

These tools are token-intensive by design and add overhead even when a chat doesn't need them.

4

Using the most capable model by default

Higher-capability models use more tokens per response than lighter, faster models.

5

High effort & extended thinking

More thorough reasoning settings produce longer, more expensive responses — useful sometimes, wasteful for routine tasks.

6

Building & iterating on artifacts

Generating and refining documents, slides, or code inside a chat adds to the running token count.

2

How to cut your usage

Six habits that meaningfully reduce token use

1

Start a fresh chat per topic

Don't let one conversation run forever; a new chat for a new topic is cheaper than extending a long thread.

2

Use Projects for repeat material

Files added to a project are cached, so reusing them across chats costs far less than re-uploading each time.

3

Turn off extras you don't need

Switch off web search, Research, and connectors for tasks that don't require them.

4

Match the model to the job

Save the top-tier model for tasks that truly need it; use a lighter model for routine work.

5

Dial down effort & thinking for routine tasks

Skip extended thinking and high effort settings unless a task genuinely needs deep reasoning.

6

Batch your asks

Combine related questions into one well-scoped message instead of several back-and-forth ones; fewer iterations means fewer artifact rebuilds too.
